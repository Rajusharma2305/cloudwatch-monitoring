# AWS CloudWatch Monitoring and Logging

## Overview

This project is based on setting up monitoring and centralized logging for a small Flask application running on an AWS EC2 instance.

Amazon CloudWatch is used to monitor the infrastructure, application, and database, as well as to collect logs in one place.

## AWS Services Used

* Amazon EC2
* Amazon CloudWatch
* CloudWatch Agent
* Amazon RDS
* IAM
* Nginx
* Python Flask

## Monitoring

### Infrastructure Metrics

The EC2 server is monitored for the following metrics:

* CPU utilization
* Memory utilization
* Disk utilization

CPU metrics are collected through the standard EC2 CloudWatch metrics. Memory and disk usage are collected using the CloudWatch Agent.

### Application Metrics

The Flask application is monitored for:

* Request rate
* Error rate
* Request latency

Test endpoints were used to generate normal, error, and slow requests so that the application monitoring could be verified.

### Database Metrics

Amazon RDS is used for database monitoring.

The following database metrics are monitored through CloudWatch:

* CPU utilization
* Database connections
* Free storage space
* Read/write activity
* Database latency

## Centralized Logging

CloudWatch Logs is used to collect logs from different parts of the application and server.

### Application Logs

Logs generated by the Flask application are collected and sent to CloudWatch.

Example information includes:

* Incoming requests
* Request completion
* Request latency
* Application errors

### System Logs

Linux system logs are collected from the EC2 instance.

Examples include:

* System activity
* Authentication activity
* System errors

### Access Logs

Nginx is used in front of the Flask application.

Nginx access and error logs are collected and sent to CloudWatch.

These logs help identify:

* Incoming requests
* HTTP status codes
* Client requests
* Web server errors

## Flask Application

The Flask application was created specifically for testing the monitoring setup.

The application contains the following endpoints:


/          - Normal application request
/health    - Health check
/error     - Generates a test HTTP 500 error
/slow      - Simulates a slow request
/metrics   - Displays system metrics

Example testing commands:

`
curl http://localhost:5000/
curl http://localhost:5000/health
curl http://localhost:5000/error
curl http://localhost:5000/slow
```

These requests generate the data required to verify the monitoring and logging setup.

## CloudWatch Dashboard

A CloudWatch dashboard is created to view the monitoring information from a single location.

The dashboard contains:

* EC2 CPU utilization
* Memory utilization
* Disk utilization
* Application metrics
* RDS metrics
* Application logs
* System logs
* Access logs

## CloudWatch Alarms

CloudWatch alarms are configured to identify abnormal conditions such as:

* High CPU utilization
* High memory usage
* High disk usage
* Application errors

These alarms can be used to notify the administrator when a defined threshold is exceeded.

## Result

The final setup provides a centralized monitoring and logging solution using AWS CloudWatch.

Infrastructure metrics, application metrics, database metrics, application logs, system logs, and access logs can all be monitored from AWS CloudWatch.

The CloudWatch dashboard provides a single view of the application's overall health and the CloudWatch alarms help identify issues when they occur.
